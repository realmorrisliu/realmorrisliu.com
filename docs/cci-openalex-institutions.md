# TEC 知识产出：机构目录与作品计数口径

核验日期：2026-10-10。完整机构目录用于建立可追溯的空间关联，不是城市科技排名或论文产出底表。现有 TEC 网络样本不能替代这一子支柱。

## 本轮冻结的资料

依据 [OpenAlex 官方快照说明](https://help.openalex.org/access/snapshot/)，下载 2026-09-23 版全部 80 个机构分区，合计 202,438,127 字节、136,136 条记录。没有按论文数量、国别、旧榜单或用户提名筛选机构。机构原始数据许可为 CC0；[来源与分区哈希](data/cci-openalex-institution-source.json)保存清单 URL、日期、每个文件的字节数及记录数。

[机构到功能区映射](data/cci-openalex-institution-fua.csv)保留全部机构 ID、ROR、类型、目录状态、原始城市／坐标、父系 ID 和映射状态。[全候选目录覆盖](data/cci-openalex-efua-directory-coverage.csv)保留全部 9,031 个候选。缺坐标、无交集及多重交集分别记录；没有匹配目录点不等于没有研究产出。

本批 120,309 条机构目录点唯一落入候选，15,826 条在冻结边界外，1 条缺坐标；没有多重匹配或无效坐标。3,880 个候选至少有一条目录点，5,151 个没有。所有记录均保留，计数与来源总数一致。

坐标来自机构 `geo`，转换后与冻结 FUA 求点面交集。其精度可能仅到城市，不能视作校园或实验室边界；更不能将全国机构的全部论文计入总部城市。`lineage` 保留供后续父子机构、跨校区与作品作者单位审计，不在本轮累加父子产出。

## 为什么不能直接累加 works_count

[实取接口响应与查询](data/cci-openalex-count-probes.json)保存一次未筛选机构探测及对首条异常计数的后续核查；这是诊断案例，不是代表性抽样。首条机构为 National Institute for Fusion Science (`I4210108322`)：

| 2025 年口径                           |     记录数 |
| ------------------------------------- | ---------: |
| 机构对象 `counts_by_year.works_count` | 18,940,306 |
| 默认 works 语料、精确机构过滤         |    388,273 |
| 默认语料中的 article                  |        256 |
| `corpus=all`、精确机构过滤            | 18,940,301 |
| 全语料中的 dataset                    | 18,099,827 |
| 全语料中的 article                    |        260 |

各作品类型聚合与其响应总数已校验一致。机构汇总与全语料作品查询仍相差 5 条，本轮未确定原因，不能自行修正为一致。第二条机构还包含 `year=10000` 等年份记录，说明不能按数组顺序截取年份或无条件累加。

[官方语料说明](https://help.openalex.org/data/works/corpus/)区分 core、expansion 和 all；[作品定义](https://help.openalex.org/data/works/)涵盖论文、数据集、预印本等不同类型。因此，上述千万级计数不能表述为千万篇论文，也不证明该机构的研究质量或城市科技能力。数据集本身可能有科学价值，问题是不能与论文按条数等价相加。

## 下一步的统一计算约束

- 明确作品类型、语料和年份窗口，再提取作品级记录；2026 年尚未结束，不能将全年 2025 与 2026 年累计量混比。
- 按作品 ID 去重；明确预印本／正式版及撤稿的处理。机构汇总不提供跨机构合作去重所需信息。
- 用发表时作者单位匹配机构及 FUA；父子机构与多城市关联需保留，不能自动归到总部。尚未匹配的作者单位保留未知份额，不重分配给已知城市。
- 合作分摊规则及规模／领域差异尚未校准。目录数量、总引用、h-index 均不直接变成 CCI 分数。

[官方机构说明](https://help.openalex.org/data/institutions/)记录 2026-09-28 更换单位匹配器；本轮机构快照早于该变更，实时 API 探测与快照不是同一版本。后续作品关联必须冻结匹配版本或明确版本不一致，不能静默拼接。

## 复算与边界

研究 Python 使用已有 Shapely、PyProj；网站无新增依赖。将来源清单中的分区下载到缓存，按 `localFile` 命名；来源 JSON 可作为缓存的 `download.json`（脚本读取其中下载元数据）。运行：

```sh
pnpm exec <research-python> -B scripts/cci_openalex_institutions.py --cache <snapshot-cache> --fua <frozen-fua-gpkg>
```

脚本验证分区哈希、逐分区及总记录数、机构 ID 唯一性和 FUA 完整性。原始压缩文件留在研究缓存，仓库保存映射与哈希。当前成果不改变统一矩阵的知识产出覆盖，也未产生城市论文数量、TEC 分数或入围资格。

## 作品获取路径与大合作作者完整性（后续核验）

[获取路径审计](data/cci-openalex-works-access-audit.json)冻结 2026-09-23 作品 Parquet 清单：2,040 个分区文件，476,196,327 条记录，707,141,690,793 字节（约 707.14 GB，十进制）。本轮只取得清单、一个文件的页脚和一个行组的必要列，没有下载全库。分区按更新日期组织，不能只取近期分区就声称取得某发表年的全部作品。

[官方作者单位说明](https://help.openalex.org/data/authorships/)指出 API 作品内作者列表受 100 人限制。实取 `publication_year:2025,type:article,authors_count:>100` 查询时，响应总命中为 2,843；首条 `W4394029306` 仅返回 100 条作者记录，虽然请求选择 `is_authors_truncated`，响应仍没有该字段。2,843 是查询命中数，不是已下载或已验证作品数。本例证明“标记未真”不能被当作作者列表完整。

改查免费快照：按清单字节数选择最大文件的第一个行组，读取 `id / publication_year / authors_count / authorships` 四列并保存本地投影副本。[离线核验](data/cci-openalex-authorship-rowgroup-audit.json)记录 46,950 条作品、37 条作者数超过 100 的作品；全部计数与列表长度一致，包含 2,920 人的列表。**这仅证明快照在该行组可保留超百人列表**，不能推广为全库没有截断、源作者名单无遗漏或单位解析正确。API 与快照时点不同，此处也不是同一作品的版本对照。

最大文件页脚中的 11 个行组，发表年份最小／最大值均跨越 2025；仅凭这些统计不能跳过任何一个行组。其他文件尚未检查，不能据这一个文件估算全库传输量。页脚哈希只覆盖页脚，不冒充完整远端文件哈希；本地四列投影另有自己的 SHA-256。

因此，后续作品归属优先验证快照中的完整作者列表。每篇先对账声明人数与列表长度，再检查作者单位；API 列表达到 100 且无可靠完整性证据时进入待审，不能把前 100 人归一化成全部合作贡献。合作分摊仍需另行解决多机构、跨城市、未识别单位及机构目录位置精度，不由本次完整性核验自动决定。

离线复算：`pnpm exec <research-python> -B scripts/cci_openalex_authorship_audit.py <saved-four-column-projection.parquet> --output <audit.json>`。新增测试验证超百人完整列表与截断列表的区别，以及重复作品拒绝；全研究测试目前 49 项通过。此次尚未产生全球城市知识产出值。

### API 列表与单条详情的区别

后续针对同一 ID 核查发现，不能将列表截断推广成所有 API 响应都截断：`W2887590359` 的单条详情返回 2,920 条作者记录，与抽查快照列表长度一致。先前在列表中只返回 100 人的 `W4394029306`，单条详情也返回超过 100 人的完整长度列表（具体长度、请求及响应哈希见获取路径审计的 `singletonProbes`）。两个详情仍没有截断标记。

因此，除快照外，还存在“取得符合统一条件的作品列表，再对达到百人上限的记录补取单条详情”的可验证路径。该路径仍须核对完整作品集合、接口预算、作者单位缺失及版本变化；单条返回更多作者本身不是与出版者原始名单一致的证明。前述优先快照是当时基于列表限制的选择，不再视为唯一可行方式。

### 全球作品类型与批量获取规模

[2025 年 core 类型清点](data/cci-openalex-2025-type-inventory.json)保存实时 API 的完整聚合响应、查询与响应哈希。25 个互异类型的计数之和与响应总数 14,746,904 一致；其中 article 7,385,754、conference-paper 961,314、review 109,308，另有 dataset 1,860,566、preprint 670,722 等。这里没有执行撤稿排除、作品版本去重或城市归属，不能将总数视为论文数；core 也不等于只有论文。

类型选择本身会影响比较：只计 article 会遗漏会议论文，而将数据集、预印本和正式发表版本按记录数等价累加又可能改变排序。后续应分别保留类型计数与未知归属，先检查同一候选在不同作品口径下的变化，再决定是否合并为知识产出指标。此处不据这些全球聚合数给任何城市评分。

按[官方分页文档](https://help.openalex.org/api/paging/)支持的每页 100 条，若取得上述全部类型，理论上至少需要 147,470 个有记录的列表页，还未计作者详情补取、重试和版本变化。该数字只是查询规模算术，不是实测请求数或费用估计。官方建议大批量下载使用快照，因此继续核验冻结快照的列读取路径；不以实时 API 总数作为 2026-09-23 快照应有记录数。

### 全量 Parquet 页脚核验

[逐文件结果](data/cci-openalex-works-metadata.csv)与[汇总及列路径](data/cci-openalex-works-metadata.json)覆盖冻结清单全部 2,040 个文件。页脚行数合计 476,196,327，与清单一致；文件声明大小合计 707,141,690,793 字节。每个页脚经范围响应、文件大小、ETag、记录数及必要列存在性校验；缓存复用时另核验页脚 SHA-256。一次 DNS 失败使首次运行未生成汇总，随后复用缓存补取缺失项，完整运行成功。

7,768 个行组都有发表年份最小／最大统计；其中 7,414 个范围包含 2025，只有 354 个可据此跳过。保留行组包含 459,294,412 条记录，**这不是 2025 年作品数**，仍须逐记录筛选。

| 保留行组内的列范围                               | 压缩列块字节数 |
| ------------------------------------------------ | -------------: |
| ID、年份、类型、扩展语料标识、撤稿标识、作者数   |  4,894,017,968 |
| 所选作者 ID／单位 ID／原始单位文本／机构谱系叶列 | 33,969,553,129 |
| 全部 authorships 叶列（与上一行重叠）            | 99,711,202,158 |

以上是元数据中的压缩列块之和，不是已经下载的作品量、实际网络传输量或完整下载预算；页脚读取共 287,962,042 字节，也不能替代全文件哈希。下一步采用两阶段读取：先取得筛选列并核验实际年份、类型、语料及撤稿状态，再读取所需行组的单位列。按行组读取仍可能包含大量不符合条件的作品，不能将筛选后记录比例直接当成网络节省比例。

复算命令：`pnpm exec <research-python> -B scripts/cci_openalex_works_metadata.py --manifest <frozen-works-manifest.json> --cache <footer-cache>`。新增测试验证年份统计缺失时保留行组、仅跳过不相交年份区间，以及缓存年份与校验和不符时拒绝读取。此阶段完成的是获取路径核验，尚未形成全球作品底表或城市知识产出值。

### 作品级筛选列实读

`cci_openalex_work_filters.py` 根据冻结页脚按范围读取六个筛选列，以稀疏临时文件交给现有 Parquet 解码器；无关列不读取。每次请求校验 ETag、范围和长度，逐行组对账行数，每个分区对账读取字节数。输出保留所有 2025 年类型、语料及撤稿状态，包括未知标识，并保留原分区、行组与行内位置，供后续单位数据关联。分区内无效或重复作品 ID 会拒绝输出；跨分区去重仍需单独完成。

[实读核验](data/cci-openalex-filter-probe.json)沿用此前最大的快照文件：400,000 条记录完整投影后得到 13,882 条 2025 年记录，读取筛选列块 4,609,552 字节。其中第一个行组的 937 条目标年份记录，与此前独立保存的四列投影按 ID、年份、作者数逐条一致。该文件不是代表性抽样，不能据此估计全球年份分布、类型分布或城市产出。

全量读取命令：`pnpm exec <research-python> -B scripts/cci_openalex_work_filters.py --footers <footer-cache> --output <filter-projection-cache>`。成功分区各有 Parquet 及 SHA-256 清单；失败项显式报告，重跑复用已校验缓存。只有全分区成功且总行数对账通过，才产生全量 `manifest.json`。本次已启动全量任务，尚未取得全量完成结果。新增三项测试覆盖与完整读取的逐值对照、位置／未知标识保留、截断与重复拒绝、无关年份零请求；55 项研究测试通过。

全量提取完成后，运行 `pnpm exec <research-python> -B scripts/cci_openalex_filter_audit.py --cache <filter-projection-cache>`。该审计要求完整分区集合及冻结元数据对账，以临时 SQLite 唯一约束检查跨分区作品 ID 和源位置，逐分区复核 Parquet 哈希、目标年份、记录数与类型／语料／撤稿状态计数。作者数未知或无效分别报告，不替换为零；出现重复不会自行择一或累加。作品 ID 唯一仍不等于预印本与正式版已去重。

新增审计测试覆盖跨分区重复、内容变更、计数不符和未知值保留，全研究测试达到 57 项。审计逻辑已在一批完成缓存上实跑，但全量提取仍在进行，尚未生成全局唯一性审计结果；部分缓存通过不能推广成全库通过。

### 作者单位的实际歧义

[作者单位定义](https://help.openalex.org/data/authorships/)区分逐条原始单位文本的匹配结果 `affiliations` 和去重后的机构列表 `institutions`；[机构定义](https://help.openalex.org/data/institutions/)说明 `lineage` 包含本机构及祖先，且部分缺少独立 ROR 的子单位只能匹配到上级机构。因此，谱系不能被当成额外研究地点，机构目录坐标也不能自动定位每篇作品的实际研究场所。

[实取行组诊断](data/cci-openalex-affiliation-rowgroup-audit.json)使用已核验的同一投影及冻结机构目录，检查其中全部 937 条 2025 年作品、6,496 条作者记录：

| 作者记录上的情况                        |  条数 |
| --------------------------------------- | ----: |
| 无任何匹配机构                          | 1,781 |
| 没有逐条 affiliation 记录               | 1,577 |
| 至少一条非空原始单位文本未匹配机构      |   315 |
| 匹配机构的目录点涉及多个 FUA            |   538 |
| 直接机构列表同时包含父子机构            |   306 |
| 至少一个机构不在冻结目录中              |    18 |
| 至少一个已入目录机构没有唯一 FUA 点匹配 |   268 |

各项可重叠，不能相加；没有 affiliation 记录也不直接证明出版者原始作品没有单位信息。此样本的逐条文本匹配 ID 并集与平铺机构 ID 集合未发现不一致，但这不是全库保证。样本选择为最大文件的首个行组，不用于估计全球缺失率。输出保留问题作品 ID、作者位置、机构 ID 和父子关系例子，便于回查。

后续城市归属必须保留未知部分；多城市和父子机构重叠进入歧义审查，不能把未知份额重新分给已知城市，也不能仅凭父子关系删除可能真实存在的双重单位。当前只识别这些情况，没有生成合作分摊值。复算：`pnpm exec <research-python> -B scripts/cci_openalex_affiliation_audit.py <verified-four-column-projection.parquet>`。相关测试验证未知不重分配、父子／跨城歧义、目录缺失与匹配差异的区分，以及不完整作者列表拒绝；59 项研究测试通过。

### 完整目录中的跨城市谱系

[谱系地点表](data/cci-openalex-hierarchy-locations.csv)和[校验汇总](data/cci-openalex-hierarchy-locations.json)进一步覆盖全部 136,136 条冻结机构记录：将每条记录关联到其非自身的 `lineage` ID，对祖先及后代的目录 FUA 点去重。有后代记录的祖先 ID 共 6,410 个，均在同版目录中；其中 3,008 个谱系涉及多个目录 FUA，1,319 个谱系至少有一个已入目录成员没有唯一 FUA 点匹配。后两项可重叠。

例如，CNRS 的 1,513 条后代记录与自身共涉及 103 个目录 FUA。这证明按机构汇总计数再落到单一总部坐标会混合不同地点；它不证明每个地点在目标年份都有科研产出，也不是 CNRS 的真实研究场所清单。谱系关系还可能包含上级祖先与合并后的继承机构，不应仅解释为直接下属或当前校区。

该表用于作品归属的歧义检查，不据此排除机构，也不把一个谱系的产出平分到全部目录地点。只出现一个 FUA、没有后代记录或目录点缺失，都不能证明是单一校区。复算：`pnpm exec <research-python> -B scripts/cci_openalex_hierarchy.py`。测试覆盖重复谱系／同城点去重、未定位成员保留，以及缺失祖先不继承后代地点；61 项研究测试通过。

### 必要作者单位列的投影等价性

为验证后续只读必要列不会损坏作者列表，在已缓存的完整行组上执行[嵌套列对照](data/cci-openalex-nested-projection-audit.json)：46,950 条作品、226,155 条作者记录的所选字段与完整记录逐值一致，包含全部 37 条超过百位作者的作品。比较保留作者顺序、空列表、空值、每条原始单位与机构 ID 的对应关系；作者列表长度也逐条与声明人数一致。它不证明出版者原始名单无遗漏或机构解析正确。

实现上必须区分 Arrow 数据集字段路径与 Parquet 物理叶列路径。实测 `pq.read_table(..., columns=<带 list.element 的物理路径>)` 报字段不匹配；`pq.ParquetFile(...).read(columns=...)` 可按冻结页脚路径重建所需嵌套结构。后续远端范围读取应使用后者，并另行对账远端数据；本次是本地缓存的投影等价性验证，不是全库单位列已经读取。
